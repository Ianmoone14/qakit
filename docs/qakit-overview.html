QAKit

The shared engine for UI and API tests. Teams write uiTest / apiTest. They install packages. They do not fork the framework.

What it does · the driver · how Playwright and API plug in · how the next package reuses the same core

Start here: this is a platform, not a copied test folder. Published GitLab pins are still 0.1.0. The driver is in git; 0.2.0 is the next Changesets publish.

What the framework does

It runs the test around the team’s code

QAKit does not replace Playwright. It starts the browser, hands over a real page, then always cleans up and keeps files.

What it takes care of

Shared concerns — once, for every adapter

If a concern is shared across 30 teams, it belongs in core or an adapter. If it names a product (SAP, checkout), it belongs in the team repo.

The reuse contract

Three primitives. Every package uses them.

LifecycleManager

Six phases. Adapters register hooks. Cleanup always runs, LIFO. Timeouts and critical flags are shared.

Same manager for browser, HTTP, and a future mobile driver.

ServiceRegistry

Adapters put live objects on the test context by key. Core never imports Playwright types.

ServiceKeys.PlaywrightPage · ApiClient · later AppiumDriver

ArtifactStore

Any adapter can save() a file. Core copies it under artifacts/<executionId>/ and attaches it to the result.

screenshot · trace · request · response · custom

A new package does not rewrite config or cleanup. It implements Extension hooks and registers a service key. Testers never call the manager unless they want the long example.

The driver

Testers write this. Core still has no Playwright.

// @qakit/playwright/test
uiTest('home loads', async ({ page }) => {
  await page.goto('https://example.com');
});

// @qakit/api/test
apiTest('health', async ({ api }) => {
  await api.request({ method: 'GET', url: '/health' });
});

// one run, two services
uiTest('checkout after seed', async ({ page, api }) => {
  await api?.request({ method: 'POST', url: '/setup', body: '{}' });
  await page.goto('/checkout');
});

The name is the kind of test

uiTest = browser page. apiTest = HTTP client. Later mobileTest = Appium driver.

Not playwrightTest — that ties the name to a vendor. Not a single test — Vitest already owns that word.

One engine underneath. The next slide is the three function names that hide it.

Do not grow the fixtures object (page, api, driver, db). Extra tools register a new ServiceKeys entry.

The driver

Three names. Same run. Different jobs.

uiTest / apiTest

What testers write. Wraps Vitest it(). Terminal is green or red. Does not return a summary — Vitest only sees pass/fail.

runUiTest / runApiTest

Same run, no Vitest. Returns ExecutionSummary after the callback. Print or assert it there — cleanup (screenshot, close browser) has not finished while you are still inside async ({ page }) => ….

runQakitTest

The engine in @qakit/core. Six phases, then the summary. No Page, no fetch types. Adapters register the device; core only runs the schedule.

// print after the callback — not inside it
const summary = await runUiTest('home', async ({ page }) => {
  await page.goto('https://example.com');
});
console.log(summary.status);

The long form (registerPlaywright + ServiceKeys) still works if you are not on Vitest. New tests should not copy it. Appium later is a new package: mobileTest({ driver }) — same runQakitTest, not a new core.

Say this out loud: core = schedule. Adapter = what gets started. *Test = hide the schedule. Summary exists only after the test body returns.

How Playwright uses the core

It is an extension, not a second framework

// qakit.playwright.json — not in qakit.config.ts
{
  "headless": true,
  "screenshotOnFailure": false
}

// long form still valid
registerPlaywright(manager);
const page = test.services.get(ServiceKeys.PlaywrightPage);
await page.goto(url);

Core never sees Page. uiTest registers Playwright and hands over a native page. File defaults lose to explicit test options.

How API uses the core

Same manager. Different service key.

apiTest('health', async ({ api }) => {
  await api.request({
    method: 'GET',
    url: '/health'
  });
}, { saveArtifacts: true });

// relative URLs use config.baseUrl

The client is generic fetch. A checkout or SAP wrapper would be a team package, never @qakit/api. No qakit.api.json — baseUrl stays on core config.

Same run, two adapters

They share the run. They do not share types.

A UI+API test is one runQakitTest. uiTest registers both when @qakit/api is installed. The packages do not import each other at runtime except an optional dynamic import.

How it stores a run

Four stores. No dashboard yet.

Config

Team file qakit.config.ts (project, baseUrl, artifacts dir). Playwright launch flags are qakit.playwright.json, read by the adapter, not core. retry is stored and unused.

Logs

Process logger. pretty or json. child() copies executionId / testId. Adapters do not invent a second logger.

Artifacts

Filesystem first. artifacts/<executionId>/<ulid>_name. Interface is ArtifactStore so object storage can replace the disk later without a contract break.

Results

In-memory TestResult + ExecutionSummary. Statuses: passed / failed / skipped / timedOut. No Allure or Xray fields in core — a reporter package can map them later.

artifacts/
  01J…EXECUTION/
    01J…_failure.png      ← Playwright
    01J…_trace.zip
    01J…_request.json     ← API
    01J…_response.json

CLI

init · version · upgrade

qakit init name

--playwright / --api choose adapters (neither = both). Core always. Playwright also writes qakit.playwright.json and a uiTest sample. Does not run install. --force for a non-empty dir.

qakit version

Prints the CLI plus whatever @qakit/* the current project resolved. Useful in CI logs.

qakit upgrade

Rewrites pins to the running CLI platform version. Does not touch team tests. Then the team runs pnpm install.

Company teams use this against GitLab. Do not use init against public npm — QAKit is not published there.

Future · what the other icebox items mean

Same core. New packages. No forks.

Allure / Xray reporters

A small package maps TestResult.status and artifacts into Allure steps or an Xray test execution. Core never grows an xrayIssue field. Teams that do not use Xray install nothing extra.

Object storage for artifacts

Replace FileSystemArtifactStore with S3 / GitLab generic packages. Same ArtifactStore.save(). Playwright and API keep calling ctx.artifacts.save unchanged.

Python data workers

Excel / CSV / ERP transforms as a sidecar, not a second UI framework. TypeScript still owns Playwright. Python writes files; tests read them. One result model if the worker reports back.

DB / auth / mocks

Another adapter: registerDb(manager) puts a client on the registry, closes the pool in cleanup. Auth already has AuthProvider.getHeaders. Mocks stay in the team repo until three teams share a real pattern.

We build these when a named team arrives with an example — not as a catalogue in core.

Takeaways

Remember these four

  1. QAKit owns the run — config, lifecycle, cleanup, logs, artifacts, results.
  2. Adapters own a device or protocol — uiTest hands a page; apiTest hands a client. Appium later is mobileTest({ driver }).
  3. Teams own the product — locators, paths, tokens, assertions. Never in core.
  4. Install packages, do not fork — GitLab npm, pinned versions, upgraded together.
